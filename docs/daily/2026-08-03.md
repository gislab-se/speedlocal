## Decisions and discoveries

- Allocation ranking was the last primary-population consumer that called
  `distance_table_for_layer()` directly. It combines group sources by minimum
  distance and any intersection, then applies a 3,000 m clearance-ranking cap;
  it does not use the interactive restriction slider value.
- The replacement keeps that formula and mixed-source behavior. The primary
  distance/intersection frame now comes from `population_acceptance_frame()`
  over the manifest-declared domain; only optional transitional sources may
  use the registry loader.
- A broken or unavailable canonical population contract now fails the ranking
  specification before any legacy distance loading.
- The canonical ranking frame is immutable for a region, canonical layer set,
  manifest default threshold, and target resolution, so it is cached across
  Streamlit reruns. This avoids repeatedly processing the 89,312-row R8
  artifact during scenario-allocation rendering.
- `built_centre` and `built_low_selection` should be manifest-migrated rather
  than removed. They are accepted optional public proxies, off by default, and
  already included in the checksum-pinned runtime package.
- `built_centre` is one `MultiPolygon` with a 89,312-row R8 distance table;
  `built_low_selection` is 10,966 points with a 89,312-row R8 distance table.
  Both use the same source-cell universe and R7/R6/R5 sparse-domain signature
  as `population_points`, allowing geometry-driven `population_polygons` and
  `population_points` adapters without a region-name branch.
